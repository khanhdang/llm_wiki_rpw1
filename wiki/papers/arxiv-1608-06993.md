In a DenseNet, each layer within a block receives the feature-maps of all
earlier layers, concatenated, and passes its own on to all later layers. An
L-layer network therefore has L(L+1)/2 direct connections instead of L. The
authors say this eases gradient flow, encourages feature reuse and cuts
parameters [src:arxiv_1608.06993 p.1].

Huang, Liu, van der Maaten, Weinberger. *Densely Connected Convolutional
Networks.* arXiv:1608.06993, 2016.

## Contribution

- **Dense connectivity.** ResNets, Highway Networks, stochastic depth and
  FractalNets all create short paths from early to late layers. DenseNet turns
  that idea into one rule: connect every layer to every later layer with
  matching feature-map size [src:arxiv_1608.06993 p.1].
- **Concatenation instead of summation.** Unlike ResNets, features are
  concatenated, not added. The authors argue that summation may impede
  information flow [src:arxiv_1608.06993 p.1] [src:arxiv_1608.06993 p.3].
- **Fewer parameters.** Layers do not need to relearn redundant feature-maps,
  so the networks are smaller [src:arxiv_1608.06993 p.2].

## Method

- **Layer function.** Layer ℓ receives [x₀, …, x_{ℓ−1}] concatenated, and its
  function H_ℓ is BN → ReLU → 3×3 conv [src:arxiv_1608.06993 p.3].
- **Dense blocks and transition layers.** The network is split into dense
  blocks. Between blocks, transition layers (BN, 1×1 conv, 2×2 average
  pooling) change the feature-map size [src:arxiv_1608.06993 p.3].
- **Growth rate k.** The number of feature-maps each layer adds. Layers can be
  very narrow, for example k = 12, because each layer sees the network's
  "collective knowledge" [src:arxiv_1608.06993 p.3].
- **Variants.** DenseNet-B adds a 1×1 bottleneck producing 4k maps before each
  3×3 conv. DenseNet-C compresses at transitions with θ = 0.5. DenseNet-BC
  uses both [src:arxiv_1608.06993 p.4].
- **ImageNet models.** DenseNet-BC with 4 dense blocks and k = 32 at depths
  121, 169, 201 and 264 [src:arxiv_1608.06993 p.4].
- **Training.** SGD with Nesterov momentum 0.9 and weight decay 10⁻⁴. On
  ImageNet: 90 epochs, batch size 256, learning rate 0.1 divided by 10 at
  epochs 30 and 60 [src:arxiv_1608.06993 p.5].
- **Memory.** A naive implementation is memory-inefficient on GPUs
  [src:arxiv_1608.06993 p.5].

## Results

- **CIFAR.** DenseNet-BC (L = 190, k = 40) scored 3.46% error on C10+ and
  17.18% on C100+, beating wide ResNets. Without augmentation, the best errors
  on C10 and C100 are close to 30% lower than FractalNet with drop-path
  [src:arxiv_1608.06993 p.6].
- **Parameter efficiency.** DenseNet-BC with L = 100, k = 12 roughly matches
  the 1001-layer pre-activation ResNet (4.51% vs 4.62% on C10+) with 90% fewer
  parameters [src:arxiv_1608.06993 p.6]: 0.8M against 10.2M
  [src:arxiv_1608.06993 p.7].
- **Capacity scaling.** Without bottleneck or compression, C10+ error drops
  from 5.24% to 4.10% to 3.74% as parameters grow from 1.0M to 7.0M to 27.2M
  [src:arxiv_1608.06993 p.6].
- **ImageNet, validation, single-crop / 10-crop.** Top-1 error is
  25.02/23.61% for DenseNet-121 and 22.15/20.80% for DenseNet-264
  [src:arxiv_1608.06993 p.6].
- **Against ResNet.** DenseNet-201 with 20M parameters matches ResNet-101 with
  more than 40M. A DenseNet with ResNet-50's compute performs on par with
  ResNet-101 [src:arxiv_1608.06993 p.7].
- **Feature reuse.** A weight heat-map shows layers spread weight over many
  earlier layers, while transition-layer outputs get little weight, which fits
  the gains from compression [src:arxiv_1608.06993 p.8].

## Limitations

- **Settings tuned for ResNets.** The ImageNet experiments reuse ResNet
  hyperparameters, so DenseNet may be under-tuned [src:arxiv_1608.06993 p.7].
- **Possible overfitting.** On C10, going from k = 12 to k = 24 slightly
  increased error (5.77% → 5.83%) [src:arxiv_1608.06993 p.6]. A 250-layer
  model did not improve on SVHN [src:arxiv_1608.06993 p.6].
- **Memory.** A naive implementation uses a lot of GPU memory
  [src:arxiv_1608.06993 p.5].
